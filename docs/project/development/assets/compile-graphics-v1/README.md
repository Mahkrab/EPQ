# Compilation graphics diagnosis

Collected on the primary PC on 24 October 2026. `diagnostic.json` and
`final-diagnostic.json` are two separate three-pair exploratory campaigns;
`qualified-diagnostic.json` is a follow-up pair. These precede the final window
transport selection. `installed-diagnostic.json` records the exact installed repair,
with the source identity in `source-and-state.json`. Do not pool the campaigns or
present these short requests as a long-run solver baseline.

Each request used the existing 48³ capacity fixture, CUDA, timestep refinement 4,
eight accepted steps, stride 1 and nine 1280×720 images. Each bundle passed
`runs validate`; accepted-state hashes match across software/hardware variants.
The fixture is generated by `tools/performance/contract.py:capacity_scene(48)`;
its configuration path remains relative to the fixture's sibling `config/`.

Commands, exit codes, ordered timings, per-frame state hashes and environment are
retained in the JSON files. Angle-bracket paths are normalised publication labels;
installed command names remain literal. Local test logs concern the laptop; PC
device and installed-window checks are identified separately. Library/device tests
exercise independent pixel probes, orientation, depth, state preservation, concurrent
renderer shutdown and failure handling. Window checks sample the actual mapped X11
window and send its normal close event. No hosted checks are claimed.

Raw command logs, bundles and earlier failures remain in private operational storage.
The original Wayland smoke test opened a window, then a subsequent launch failed
with a reset connection. WSLg's service log reported Weston exiting with signal 11.
A later X11 launch during that restart also failed; clean X11 window checks passed
again once the compositor recovered. The PC therefore selects X11 for Maelstrom.
Underlying native Wayland reliability is not claimed to be repaired.
