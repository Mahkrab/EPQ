## Scope and outcome

The [milestone evaluation](/docs/project/development/milestones/01/serial-uniform-grid.md) assesses
search correctness, deterministic simulation equivalence, public usability and performance separately.
It explains the implementation choices, diagnosed problems, tested range and accepted limitations,
then gives the multithreaded implementation a concrete set of inherited contracts and evidence.
The [paired PC results](/docs/project/development/milestones/01/assets/performance-comparison-pc-v1/README.md)
support mixed performance at small sizes and increasing benefit at larger sizes, reaching 1.618× at
8,000 particles with exact output agreement. The evaluation and local completion checkpoint are complete.

## Decisions and documentation

The original numerical reference and historical datasets remain identifiable. The grid's rounded
distance coverage, overflow validation and stable row ordering are explained as search decisions;
they are not presented as retrospective changes to the physics. The implementation record remains
the detailed owner of the construction and verification history.

The Maelstrom README now exposes both supported searches. Input and usage documentation explain
execution versus physical identity, explicit library selection, backend-preserving replay, per-step
grid rebuilding, dense storage and the cost of fresh independent audits outside solver timing.
The measurement protocol clarifies the existing grid timing boundary and paired collector commands
without changing numerical or sampling policy. Source and tests remain at the assessed implementation;
Maelstrom changes in this evaluation are documentation only, committed as
[`2156bdca7f6702cea18030a8b0c603dfa393e036`](https://github.com/Mahkrab/Maelstrom/tree/2156bdca7f6702cea18030a8b0c603dfa393e036).
Its source, tests, inputs and reference outputs are unchanged from the measured implementation.

The handoff retains both serial controls, frozen manifests/goldens, exact grid outputs and datasets.
It requires immutable Jacobi inputs, fixed prediction membership, strict support, stable identity,
ordered projection, independent diagnostics and atomic acceptance. The existing quantity-specific
parallel budgets apply only where their policy permits numerical differences; they do not excuse
changed inputs, solver work or warning/failure classifications. No threading, CUDA or rendering is
implemented here.

## Verification

The local release suite passed 178 integration tests, five unit tests and two doctests under
Rust/Cargo 1.98.1 on x86_64 WSL2 Ubuntu 24.04.5. The same suite passed on the primary PC before
collection. The final 19 collector tests passed on both devices, and the three Markdown unit tests
and milestone asset check passed locally.

Both retained grid correctness outputs were checked against their goldens with zero tolerance,
including signed zero, intermediate checkpoints, audits and CFL outcomes. Their documented run
commands and public replays reproduced those outputs. All 80 recorded implementation hashes and
the frozen input/policy hashes matched. The old PC baseline report regenerated byte for byte.
New dataset integrity, all 70 complete physical outputs, source/collector provenance, primary
statistics, throughput, profile proportions and speedup ratios passed independent checks. Both
backend reports and the comparison regenerated byte for byte. Changed-document links and pinned
source targets were checked locally. No hosted rendering or CI result is inferred from these checks.

## Limitations and Gate G02

The evaluation, handoff and local checkpoint satisfy **G02**. The accepted
limits include dense interaction storage, unmeasured memory, possible quadratic fallback validation,
shared-host timing variability and the inherited numerical qualification envelope. Exact reference
agreement and faster solver execution cannot establish improved physical accuracy.

Annotated `milestone-01/phase-02/complete` and `milestone-01/complete` tags identify the local
completion checkpoints in both histories. The parent gitlink retains the final Maelstrom documentation
commit alongside its evaluation and evidence. These checkpoints do not claim remote publication,
hosted verification or completion of the wider project.
