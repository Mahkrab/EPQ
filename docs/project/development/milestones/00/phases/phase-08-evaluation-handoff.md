## Decisions and implementation

The main page became the evaluation owner, while earlier phase records and repair records retain
their historical decisions. This avoids rewriting the original design as though the axis-projection,
regularisation, energy and large-impact failures had been anticipated. The current contract's stale
open questions were reconciled against implemented resolution and comparison rules; the plan's
four-iteration statement now reflects the recorded eight-iteration revision. Earlier local gate
notes are followed by current checkpoint evidence rather than erased.

All six M00 requirements are assessed as met within their stated headless reference scope. That
assessment depends on independent calculations and health checks as well as deterministic goldens.
The evaluation explicitly separates numerical consistency from visual plausibility and physical
CFD validation. Boundary density deficiency, empirical corrections, unqualified inputs and duration
limits remain accepted limitations of this reference, not implicit tasks for the grid milestone.

The handoff links each inherited interface and numerical contract to its owner. Uniform-grid
discovery must preserve exact membership, ascending serial reductions and numerical bits; the
future parallel error budgets do not apply to it. The primary PC dataset remains the performance
reference. Laptop results and the earlier pilot remain separate; no timings were selected across
machines or reclassified as a new campaign.

## Verification

Fresh checks ran locally on 15 October 2026 using x86_64 WSL2 Ubuntu 24.04.5, Rust/Cargo 1.98.1
and Python 3.12.3. Cargo commands used locked/offline dependencies, with display variables unset
for execution checks. Both debug and release passed 159 integration tests and three unit tests;
separate doctest runs passed two tests per profile. Formatting, all-target/all-feature checking,
strict Clippy and strict Rustdoc passed. The 15 parent baseline/Markdown tests and asset-policy
check passed. No assertions or fixtures were weakened.

Documented discovery, validation, inspection, named/external execution, duration, explicit overrides,
zero steps, checkpoints, result/snapshot publication and replay were exercised through the release
CLI. Both TOML examples parsed and validated. The canonical result matched every golden numerical
value after excluding build context; replay was byte-identical within the build. Existing-file
refusal and invalid checkpoint usage produced their documented exits. The subprocess suites also
cover numerical failure, real SIGINT, warning retention and output-channel failure.

The PC report regenerated byte for byte. All 35 raw hashes, the correctness hash and golden
agreement, manifest hashes, 76 measured source-file hashes and combined tree fingerprint matched
their retained identities. Collector/protocol hashes were checked against their recorded EPQ
revision, including the protocol bytes before the later device annotation. Independently recomputed
sample statistics and stage totals agreed within accumulation roundoff. This verifies retained
evidence rather than a new PC execution. Local file/anchor links, pinned implementation targets,
Markdown fences and both repositories' whitespace checks passed.

Checkpoint verification was repeated locally on 17 October 2026: the same Rust and parent suites
passed, both documented TOML examples validated, a release-CLI example replayed byte for byte,
and the retained PC data and provenance checks passed. No new benchmark campaign was run.
