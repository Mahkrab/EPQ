# CUDA audit: review by file

This accompanies the [audit findings](/docs/project/development/milestones/05/performance-cuda-code-audit.md).
The scope is CUDA execution and the Rust code it actually calls, with CPU equations inspected
as the compatibility reference. A CPU-only function being expensive is not evidence that CUDA
runs it. Links below navigate the live checkout; the
[audit receipt](/docs/project/development/milestones/05/assets/cuda-code-audit-v1/audit.json) records
reviewed-file hashes, the full measured source identity and the immutable reconstruction basis.
This is a responsibility and performance review, not a line-coverage or hardware-certification claim.

## Native implementation

| File | Assessment |
| --- | --- |
| [bridge.cpp](/Maelstrom/native/bridge.cpp) | Main orchestration concern, F02/F03. Context lifetime is isolated and driver errors invalidate uncertain state. However, `solver_call` drains every storage/solver request, including satisfied reservations. Copies are synchronous and use ordinary host vectors; no pinned staging, asynchronous copy API, graph replay or event-based observation is implemented. Operation 13 batches host submission but retains every bitonic kernel. Reserve/upload calls repeat capacity checks. The plain C ABI is reasonable; redesign granularity behind it. |
| [solver.cu](/Maelstrom/native/solver.cu) | Main arithmetic concern, F05/F06/F08. Global Jacobi dependencies are correctly expressed through ordered launches; there is no unsafe block-local substitute for a grid barrier. One lane owns a variable row and repeatedly gathers geometry. Prefix reuse is present, but density, owner, suffix, validation and correction traversals still repeat work. The operation branch is uniform per launch; it is not itself warp divergence. Exact checking and CPU-compatible arithmetic constrain fusion. Inspect generated code before claiming repeated calls survive compilation. |
| [neighbours.cuh](/Maelstrom/native/neighbours.cuh) | F04. Compact rows fixed the old quadratic allocation. Nine binary searches plus candidate scans are repeated for count and fill; there is no cell-range directory. Sorted cell indices do not rearrange particle storage. Power-of-two widths and 64-bit coordinates protect difficult domains but have a normal-case cost. `validate_pairs` deliberately adds all-pairs checks for an extreme overflow domain; dense rows can also approach quadratic actual membership. |
| [row_sort.cuh](/Maelstrom/native/row_sort.cuh) | Retain the measured cooperative sorting. Bounded rows use complete-warp register networks, with explicit sentinel padding and heapsort beyond 256 entries. Dense fallback serialises a long row onto lane zero; measure its frequency before replacing it. This is row sorting, not the separate global cell sort. More shared memory or larger blocks are not automatic improvements. |
| [power.cuh](/Maelstrom/native/power.cuh) | F05. The general binary64 approximation and indexed constant tables are a deliberate host-rounding compatibility burden inside pair correction. Integer exponent 4 is not specialised. Constant-to-global placement was already tried unsuccessfully; separate power arithmetic cost from the rest of correction before another change. The supported positive-domain guard is not a general replacement for every host `powf` input. |
| [solver.h](/Maelstrom/native/solver.h) | F04/F08. Explicit layouts and compile-time size/offset checks are good. Separate attribute buffers already exist; each vector is still a 12-byte XYZ record. Cell records are 32 bytes and row offsets are 64-bit. Component SoA, narrower normal-domain keys and mapped spatial storage deserve measured variants, not a whole public Rust-layout rewrite. Numeric operations, slots and quantity codes are manually coupled across files. |
| [kernels.cu](/Maelstrom/native/kernels.cu) | Only includes probe and solver in one PTX module. It does not launch work or explain the steady-state runtime. Separate entry points did not establish a useful previous speedup; file splitting alone is maintainability work. |
| [roundtrip.cu](/Maelstrom/native/roundtrip.cu) | Independent transfer-layout probe. Its fixed 128-thread launch belongs to the probe, not every solver kernel. It is not executed per simulation step. Keep it for qualification; optimising it does not speed up PBF. |
| [probe.h](/Maelstrom/native/probe.h) | Plain ABI records with size and offset assertions. No particle serialisation framework or process boundary is hidden here. No material steady-state finding. |
| [tests.cpp](/Maelstrom/native/tests.cpp) | Injected-driver tests cover setup/cleanup, storage, stream ordering, partial launch failures, diagnostic groups and fill/sort submission. They are valuable guards for F02. A fake driver cannot qualify real asynchronous hazards, device races or hardware throughput; new residency/async work will need real device tests. |
| [power-LICENSE](/Maelstrom/native/power-LICENSE) | Provenance/licence companion to the adopted approximation. Keep attribution if the implementation changes; it has no runtime cost. |

## Rust CUDA boundary

| File | Assessment |
| --- | --- |
| [cuda/solver.rs](/Maelstrom/src/cuda/solver.rs) | F01/F07. Scratch persists but accepted state is reloaded each step. Recreates settings and reference weight, packs fresh arrays, downloads velocities/positions/counts for host calculations, and downloads final arrays to reconstruct particles. Geometric row-capacity growth is sensible and avoids a silent neighbour cap. These ownership and observation decisions deserve a coherent redesign. |
| [cuda/native.rs](/Maelstrom/src/cuda/native.rs) | F02/F07. Unsafe code is contained, transfer types are restricted and handles are thread-confined. Each upload reserves first; each download allocates and zero-initialises a fresh vector. The synchronous slice-borrow contract prevents overlap. Use owned reusable staging and completion-aware lifetimes rather than weakening Rust safety or making a handle shared without a model. |
| [cuda/mod.rs](/Maelstrom/src/cuda/mod.rs) | Resource/device metadata, explicit errors and the independent probe. Context construction and PTX loading are setup, not per-pair work. No hidden CPU-solver fallback once CUDA is selected. HostAllocation's probe-oriented wording is a diagnostic-quality issue, not a performance cause. |
| [cuda/solver_tests.rs](/Maelstrom/src/cuda/solver_tests.rs) | Strong quantity/stage ordering, retry, support, identity, dense-row and tail tests. Includes independent two-particle and integer-row expectations alongside CPU component comparisons. Tests cover all four block sizes for correctness; that does not select the fastest block. Keep these distinctions when revising arithmetic or storage. |
| [cuda/correction_tests.rs](/Maelstrom/src/cuda/correction_tests.rs) | Divergent powers, coincidence/support transitions, repeated attempts and bitwise CPU comparison at all block sizes. Useful compatibility coverage; neither representative long-run fluid quality nor isolated power-performance attribution. |
| [cuda/search_tests.rs](/Maelstrom/src/cuda/search_tests.rs) | Irregular missing columns, reversed spatial/identity order, duplicates and storage reuse test discovery correctness against brute force. Useful for F04; throughput of evolved or pathological dense rows is a separate question. |
| [cuda/vorticity_tests.rs](/Maelstrom/src/cuda/vorticity_tests.rs) | Stage separation, boundary distances, failure and retry coverage. Does not establish the best scheduling of confinement/XSPH; current enabled effects each add their own passes and host completions. |

## Rust simulation and numerical dependencies

| File | Assessment |
| --- | --- |
| [simulation/mod.rs](/Maelstrom/src/simulation/mod.rs) | F01/F07. The CUDA branch returns before CPU numerical loops. Accepted state is immutable to callers, but host ownership forces materialisation after every step. Input validation repeats before a step, followed by final identity/finite checks and an N-by-plane loop. Transactional semantics are necessary; their current CPU implementation is not the only possible ownership design. |
| [simulation/state.rs](/Maelstrom/src/simulation/state.rs) | Full-vector snapshots and ordered identity/finite validation. Clear invariants, but structural identity checks on private unchanged identities repeat. Separate what can change numerically from what construction already guarantees; do not remove final numerical validation without replacement. |
| [simulation/timing.rs](/Maelstrom/src/simulation/timing.rs) | Disabled stage clocks use a const generic; ordinary step calls do not deliberately read per-stage clocks. Enabled intervals are coordinated wall time and may include waits. They are not isolated device arithmetic timings. No evidence that the clock implementation explains the large gap. |
| [simulation/error.rs](/Maelstrom/src/simulation/error.rs) | Typed failures and retained accepted outcomes. Main importance is preserving rollback/cancellation obligations across a resident implementation. Formatting occurs on failure; no ordinary hot-loop bottleneck identified. |
| [fluid.rs](/Maelstrom/src/fluid.rs) | PBF parameter construction is called by CUDA settings; CPU density/gradient/correction loops are not the CUDA numerical path. Those equations define signed density constraints, ordered self insertion and host `powf` compatibility. Audit their contract's cost and quality implications instead of incorrectly attributing their CPU allocations to CUDA. |
| [kernel.rs](/Maelstrom/src/kernel.rs) | Host Poly6 is used while recreating CUDA settings. CPU functions repeatedly compute normalisation and check results; device equivalents are in solver.cu. Cache immutable coefficients only after checking generated code and error visibility. Changing squared-distance arithmetic or reciprocal multiplication can change rounding. |
| [math.rs](/Maelstrom/src/math.rs) | Small binary32 value type; no opaque allocation or dynamic dispatch. Checked lengths underlie host CFL/bounds validation. Struct size alone does not select a GPU layout; device representation is explicitly separate. |
| [boundary.rs](/Maelstrom/src/boundary.rs) | CUDA uses normals/offsets for packing and host `contains` for final acceptance. The retained inlining fix is present. Axis-contact handling preserves exact containment. Keep the invariant but investigate device-side final plane checks in F01. |
| [diagnostics.rs](/Maelstrom/src/diagnostics.rs) | CFL is a serial host maximum-speed pass requiring an accelerated-velocity download. Its measured CPU cost is modest. Density auditing deliberately invokes CPU brute force and can dominate large requested checkpoints, F10; it is outside solver timing and not called by ordinary compile. |
| [integration.rs](/Maelstrom/src/integration.rs) | CPU equations/reference for acceleration, prediction and reconstruction. CUDA implements these on device; making these Rust functions threaded would not accelerate CUDA. Their rounding and validation remain compatibility obligations. |
| [validation.rs](/Maelstrom/src/validation.rs) | Small checked scalar/vector helpers used in host setup, CFL and acceptance. Do not infer their dynamic cost by counting calls in source. Valid finite inputs can still overflow intermediate arithmetic. |
| [error.rs](/Maelstrom/src/error.rs) | Shared numerical error taxonomy. Important for exact failure semantics, not ordinary arithmetic throughput. |
| [execution.rs](/Maelstrom/src/execution.rs) | Supported CUDA block sizes are 32/64/128/256. Simulation intentionally gives CUDA no Rayon CPU pool. More CPU workers are not an omitted switch that parallelises device work. A separate application encoding pool remains possible. |
| [config/resolved.rs](/Maelstrom/src/config/resolved.rs) | Configuration is privately cloned into Simulation and PBF parameters validated on request. CUDA recreates parameters every step despite immutability. Setup parsing/provenance is distinct from the hot loop. |
| [config/validation.rs](/Maelstrom/src/config/validation.rs) | Defines supported precision, fixed timestep, ordering and iteration domains; deriving lattice values is setup work. Performance experiments can revise quality settings explicitly, but accepted policy strings must not silently change meaning. |
| [neighbours.rs](/Maelstrom/src/neighbours.rs) | CUDA uses SearchBackend as an execution requirement; it bypasses the CPU discover implementation during stepping. CPU brute force is still reached by independent density audits. The CPU uniform-grid implementation was not performance-audited here. |
| [velocity.rs](/Maelstrom/src/velocity.rs), [velocity/vorticity.rs](/Maelstrom/src/velocity/vorticity.rs) | CPU reference equations and tests, bypassed by CUDA stepping. Device operations 14–17 implement effects; their extra traversals/completions belong in enabled-effect measurements. Fixed prediction-time membership persists into these effects by contract. |

## Application, observation and build boundaries

These files were inspected for their effect on the CUDA path; this does not claim an audit of
every parser, UI feature, shader or unrelated input format in the application.

| File | Assessment |
| --- | --- |
| [application/mod.rs](/Maelstrom/src/application/mod.rs) | Controller creates a worker and publishes accepted observations. It is a lifecycle boundary, not a CUDA CPU-worker pool. Keep UI polling separate from solver timing. |
| [application/worker.rs](/Maelstrom/src/application/worker.rs) | The live worker clones the complete host snapshot after every accepted step even if the viewer draws less often. This is separate from offline compile and solver-only timing, but reinforces host materialisation costs. Consider observation demand/cadence before changing publication semantics. |
| [workflow/mod.rs](/Maelstrom/src/workflow/mod.rs) | F10. Numerical timers wrap stepping; copies, checkpoint audits and output occur outside. Input is captured and revalidated during setup, and final snapshots retained. Requested checkpoint audits can be quadratic. A faster solver timer can coexist with a slow whole command. |
| [workflow/record.rs](/Maelstrom/src/workflow/record.rs) | Portable snapshots copy every particle; JSON encoding validates records. Initial input capture clones the scene and replaces its particle vector before recording it, adding setup memory churn. Necessary provenance need not require repeated full copies on presentation-only paths. |
| [workflow/measurement.rs](/Maelstrom/src/workflow/measurement.rs) | Retains accepted step measurements and construction/teardown durations. Keeping observations separate is good; it does not expose every compilation component. |
| [workflow/output.rs](/Maelstrom/src/workflow/output.rs) | Atomic non-replacing publication flushes each staged file before linking it. That is a deliberate reliability cost on the synchronous compile path. Streaming and worker scheduling must preserve publication/failure guarantees. |
| [export/mod.rs](/Maelstrom/src/export/mod.rs) | F09. Eager full snapshots even on skipped frames, synchronous writer calls and growing progress history. Current timers omit hashing/progress/publication. Offline graphics has no window surface; no per-frame WSLg presentation occurs here. |
| [export/offscreen.rs](/Maelstrom/src/export/offscreen.rs) | F09. Creates depth/colour/readback resources per frame, waits for mapped pixels, copies rows, encodes synchronously, publishes, and hashes pretty-printed snapshot JSON. Introduce reusable resources and a bounded completion/encoding model before adding unbounded threads. |
| [export/source.rs](/Maelstrom/src/export/source.rs) | Validates saved inputs/schedules and compares requested rerun snapshots. It does not make an ordinary direct compile perform density audits. Saved/rerun parsing can add setup memory cost and should remain distinct from new simulation timing. |
| [render/gpu.rs](/Maelstrom/src/render/gpu.rs) | F09. Hardware selection is separate from CUDA device selection. CPU view-relative packing, new geometry buffers and host upload occur per draw; no CUDA buffer sharing. WSL OpenGL can use Mesa/D3D12, while explicit software selection uses CPU graphics. |
| [presentation/colours.rs](/Maelstrom/src/presentation/colours.rs) | Kinetic energy is computed during CPU frame packing using binary64. It is a presentation cost, not solver physics. Camera/colour computation could migrate to drawing code only with the current visual/numerical range policy preserved. |
| [cli/selection.rs](/Maelstrom/src/cli/selection.rs) | Default 128 is a resource policy, not a measured optimum. Auto performs a CUDA context probe before constructing the actual solver, adding setup work. Explicit CUDA failures do not silently fall back during a run. |
| [cli/pacing.rs](/Maelstrom/src/cli/pacing.rs) | Intentional real-time waits occur after acceptance for paced headless runs. The retained solver campaign used unpaced execution; compile's loop does not invoke this pacer. Do not attribute explicit pacing to poor kernel throughput. |
| [build.rs](/Maelstrom/build.rs), [Cargo.toml](/Maelstrom/Cargo.toml) | CUDA uses NVCC O3 with explicit precise arithmetic and target 89 by default; the bridge uses O2, and ordinary Rust release optimisation applies. PTX is JIT-loaded once per context. Native Windows CUDA is currently rejected, so a native-Windows comparison requires porting. More aggressive Rust flags already had a small mixed result; a C++ rewrite or fast-math switch is not an established fix. |

The review found architectural and numerical-performance constraints, not a reason to undo
the already measured prefix or cooperative-sort changes. The main audit distinguishes the
changes that preserve exact behaviour from those requiring a newly qualified numerical contract.
